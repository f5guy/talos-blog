01

Giới thiệu Talos Linux

Talos Linux là gì?

Talos Linux là một operating system immutable (bất biến) được thiết kế đặc biệt để chạy Kubernetes — từ single-node lab cho đến multi-region, multi-cluster production với hàng nghìn node.

Không phải là "một distro Linux nữa", Talos Linux là một API-driven OS: mọi thứ — từ cài đặt, cấu hình mạng, điều chỉnh kubelet, đến nâng cấp cluster — được thực hiện thông qua Talos Machine API (gRPC), không phải qua SSH hay shell.

Lịch sử phát triển

Thời gianSự kiện
2018Sidero Labs (Talos Systems) bắt đầu dự án, ban đầu gọi là Talos
2020Public alpha, hỗ trợ bare-metal K8s deployment
2021Talos v0.9 — hỗ trợ nhiều CNI, ổn định cho production sớm

2023Talos v1.5 — System Extensions, Image Factory, Airgap

Talos Linux là dự án open source (Apache 2.0) do Sidero Labs phát triển và duy trì, với một cộng đồng đóng góp rộng khắp trên GitHub.

Mục tiêu thiết kế

01

02

Triết lý: "Kubernetes OS, not a Linux distribution"

Talos Linux không phải là một distro Linux để SSH vào. Nó là nền tảng vận hành Kubernetes — được quản lý hoàn toàn qua API, bất biến, và tối ưu cho container workload.

Bạn không gõ sudo apt install nginx trên Talos. Bạn không vi /etc/ssh/sshd_config. Bạn không systemctl restart kubelet. Nếu bạn cần một thứ đó — khả năng cao bạn đang dùng sai cách.

Minh họa: "Snowflake Node"

Hai node cùng cài "Ubuntu 22.04" nhưng theo thời gian lại trôi dạt (drift) thành hai cấu hình hoàn toàn khác nhau:

Tools htop, vim, curl

/etc/hosts đã sửa để debug

Kernel 6.18.38
kubelet 1.36.2
Docker Không cài
Tools htop
sysctl Mặc định
/etc/hosts Sạch

Bốn dòng đầu giống nhau, nhưng từ SSH trở xuống thì mỗi node một kiểu — đây chính là snowflake server kinh điển: không node nào giống node nào, không thể tái tạo.

Talos giải quyết như thế nào?

Trên Talos, mọi node đều giống hệt nhau và được enforce qua MachineConfig — không thể drift:

SSHKHÔNG
Package managerKHÔNG
ShellKHÔNG (trừ maintenance mode)
FilesystemRoot READ-ONLY
StateChỉ ở /var/talos (đã mã hóa)
Kết luận: Khi chạy Kubernetes, OS ideal nhất là OS chỉ chạy Kubernetes — không có gì khác. Talos Linux sinh ra để làm đúng thứ đó.

Talos Linux Architecture

Kiến trúc tổng quan

Chi tiết các thành phần

KernelLinux 6.x
Hardened kernel với sysctl mặc định tối ưu cho K8s. Không cho thay đổi kernel module (trừ System Extensions). Default: net.ipv4.ip_forward=1, net.bridge.bridge-nf-call-iptables=1…
init — s6-overlayPID 1
PID 1 của Talos là s6-init (không phải systemd). s6 quản lý lifecycle toàn bộ services theo thứ tự dependency; service crash sẽ tự restart.
apid — Talos API Daemon❤ trái tim
Trái tim của Talos Machine API. gRPC server trên port 50000. Tiếp nhận mọi yêu cầu: get, set, apply, upgrade, reset, reboot… Tương tác trực tiếp với machine config trong /etc/talos.
containerdCRI
CRI implementation mặc định. Talos quản lý runtime, không cho user can thiệp trực tiếp. Hỗ trợ CRI v1 API, compatible với kubelet.
kubeletnode agent
Được Talos quản lý (start, configure, monitor). Không chạy như systemd service — chạy như một Talos Machine Service. Cấu hình trong MachineConfig (kubelet block).
trustdtrust daemon
Quản lý PKI certificates. Khi node join, trustd request cert từ control plane. Certs rotate tự động (default 1 năm). Hỗ trợ mTLS cho API.
machinedmachine daemon
Quản lý machine identity & hardware abstraction. Xử lý disk partitioning, boot config. Hỗ trợ reset (xóa cluster membership) và maintenance mode.
etcdControl Plane only
Lưu trữ toàn bộ Kubernetes state: pods, services, configs, secrets. Talos quản lý (không phải kubeadm). Hỗ trợ snapshots. Requires quorum: 3 hoặc 5 CP nodes cho HA.

Triết lý Immutable Infrastructure

Immutable OS là gì?

Immutable infrastructure = OS không thay đổi sau khi deploy. Không apt install, không systemctl, không vi. Nếu cần thay đổi → build lại từ đầu (re-provision).

Traditional Linux — Mutable
├── /usr/bin/* user installed
├── /etc/* admin modified
├── SSH access
├── Package manager (apt)
├── Shell access (bash)
└── Drift over time ⚠️
Talos — Immutable
├── Root filesystem: READ-ONLY
├── Package manager: NONE
├── SSH: DISABLED
├── Shell: DISABLED
├── /etc/talos/* config
└── /var/talos/* state

Cấu trúc filesystem Talos

filesystem
/
├── bin/          → Read-only (managed by Talos)
├── etc/talos/    → MachineConfig runtime (writable, apid)
├── var/
│   ├── talos/    → State: certificates, config, runtime
│   ├── lib/containerd/ → Container state
│   ├── lib/kubelet/    → Kubelet state
│   └── etcd/     → Etcd data (Control Plane)
├── boot/         → Kernel, initramfs
├── run/          → Runtime data (tmpfs)
└── tmp/          → Temporary files

State ở đâu?

TypeMountPersistenceNội dung
ROOT/Read-only (squashfs)OS binary, kernel, services
STATE/var/talosPersistent diskCertificates, configs, machine ID
EPHEMERAL/var/lib/etcd…Persistent diskK8s data, container layers
INSTALLER/installerBoot media onlyInstaller image (ephemeral)

Quan trọng: STATE partition được encrypted mặc định bằng LUKS. EPHEMERAL có thể được encrypt.

MachineConfig — Source of Truth

⚠️ Production Tip
Luôn version control MachineConfig. Không bao giờ chỉnh sửa trực tiếp trên node. Cần thay đổi → edit YAML → talosctl apply-config.

API-driven OS

talosctl là công cụ chính để tương tác với Talos Linux. Nó giao tiếp qua gRPC API trên port 50000.

Thiết lập & cấu hình node

bash
# Cài đặt talosctl
curl -sL https://talos.dev/install | sh

# Thiết lập context (nối đến cluster)
talosctl config endpoint <control-plane-IP>
talosctl config node <control-plane-IP>
talosctl config context <cluster-name>

# Verify connection · xem cấu hình hiện tại (YAML)
talosctl health
talosctl get machineconfig -o yaml

Apply & Patch cấu hình

bash
# Apply từ file YAML (+ --dry-run / --mode=no-reboot)
talosctl apply-config --nodes <node-ip> --file machine-config.yaml

# Patch một field cụ thể (JSON Patch — RFC 6902)
talosctl patch machineconfig --nodes <node-ip> \
  --patch '[{"op":"replace","path":"/machine/install/disk","value":"/dev/nvme0n1"}]'

Rollback, Upgrade & vòng đời node

Talos không có lệnh rollback tự động cho MachineConfig — rollback đúng là apply lại file YAML phiên bản trước (lấy từ Git).

bash
# Rollback: apply lại MachineConfig phiên bản trước từ Git
talosctl apply-config --nodes <node-ip> --file mc-previous.yaml

# Upgrade Talos (rolling, nhiều node) · --preserve --stage giữ dữ liệu
talosctl upgrade --image ghcr.io/siderolabs/installer:v1.13.6 \
  --nodes 10.0.0.1,10.0.0.2,10.0.0.3

# Reset node khỏi cluster · Reboot · Shutdown
talosctl reset   --nodes <node-id> --system-labels-to-wipe STATE,EPHEMERAL --reboot
talosctl reboot  --nodes <node-id> --mode powercycle
talosctl shutdown --nodes <node-id>
⚠️ Maintenance Mode
Bật qua kernel parameter talos.maintenance=true để debug. Phải tắt sau khi dùng xong — để lâu là security risk.

TPM 2.0 & Disk Encryption

TPM lưu trữ hardware-bound keys cho disk encryption (LUKS), machine identity, và certificate signing. Talos hỗ trợ encrypt disk bằng LUKS 2.0.

yaml · machine-config
machine:
  encryptDeviceKeys: true     # Encrypt device keys trong TPM
  encryptEphemeral: true      # Encrypt ephemeral (container data)
  encryptLabels: true         # Encrypt volume labels

VIP — Virtual IP (High Availability)

VIP là IP ảo dùng chung cho control plane, được Talos quản lý nội bộ (một node giữ VIP, bầu chọn qua etcd — không cần keepalived/haproxy).

yaml · VIP
machine:
  network:
    interfaces:
      - interface: eth0
        vip:
          ip: 10.0.0.100   # VIP đặt tại interface (không phải cluster)

Cấu hình interface — DHCP, Static, Bonding, VLAN, Bridge

yaml · machine.network.interfaces
# DHCP
- interface: eth0
  dhcp: true

# Static IP + route
- interface: eth0
  addresses: [10.0.0.5/24]
  routes:
    - network: 0.0.0.0/0
      gateway: 10.0.0.1
  mtu: 1500

# Bonding (LACP 802.3ad)
- interface: eth0
  bonds:
    - interface: bond0
      mode: 802.3ad
      links: [eth0, eth1]

# VLAN · Bridge
- interface: eth0
  vlans:
    - {interface: vlan100, vlanId: 100, addresses: [10.0.100.5/24]}
  bridges:
    - {interface: br0, addresses: [10.0.0.5/24], links: [eth0]}

DNS & NTP

yaml · machine.network
network:
  mtu: 9000                 # jumbo frames
  dns:
    nameservers: [1.1.1.1, 8.8.8.8]
  ntp:
    servers: [time.google.com, time.cloudflare.com]
    disableNTP: false
✅ Production Tip
Luôn cấu hình NTP chính xác. Time drift gây certificate expired, etcd leader election fail, và scheduling issues.

User Volumes & Extra Disks

Bạn có thể khai báo user volumes để mount thêm disk (ví dụ cho Ceph OSD) trực tiếp trong MachineConfig:

yaml · machine.disks / volumes
machine:
  disks:
    - device: /dev/sdb          # disk phụ
      partitions:
        - mountpoint: /var/mnt/data
          size: 0                # 0 = dùng hết disk
  # Raw disk cho Ceph — để trống, không partition/format
  # Ceph sẽ tự quản lý /dev/sdc như một OSD
⚠️ Lưu ý
Talos không tự động resize hay reformat disk đang có data. Thay đổi disk layout thường yêu cầu wipe + re-provision.

Patches — Chỉnh sửa có mục tiêu

Thay vì maintain nhiều file YAML lớn, dùng patches để override từng field — kết hợp base config + strategic/JSON patch cho từng nhóm node.

bash · patch
# patch.yaml (strategic merge)
machine:
  kubelet:
    extraArgs:
      max-pods: "250"

# Áp patch khi generate config hoặc apply
talosctl gen config my-cluster https://10.0.0.100:6443 \
  --config-patch @patch.yaml
talosctl apply-config --nodes 10.0.0.4 --config-patch @patch.yaml
✅ Best Practice
Giữ một base config chung + các patch nhỏ theo role/node. Tất cả trong Git, review qua PR.

Bootstrap Cluster từ đầu

bash · full bootstrap
# 1. Generate config (tạo controlplane.yaml, worker.yaml, talosconfig)
talosctl gen config my-cluster https://10.0.0.100:6443

# 2. Apply cho control plane nodes
talosctl apply-config --insecure --nodes 10.0.0.1 --file controlplane.yaml
talosctl apply-config --insecure --nodes 10.0.0.2 --file controlplane.yaml
talosctl apply-config --insecure --nodes 10.0.0.3 --file controlplane.yaml

# 3. Apply cho workers
talosctl apply-config --insecure --nodes 10.0.0.4 --file worker.yaml

# 4. Bootstrap etcd — CHỈ chạy MỘT LẦN, trên MỘT CP node
talosctl bootstrap --nodes 10.0.0.1 --endpoints 10.0.0.1 --talosconfig=./talosconfig

# 5. Lấy kubeconfig
talosctl kubeconfig --nodes 10.0.0.1 --endpoints 10.0.0.1 --talosconfig=./talosconfig
kubectl get nodes
🚨 Cảnh báo
talosctl bootstrap chỉ được chạy MỘT lần duy nhất trên MỘT control plane node. Chạy nhiều lần sẽ phá hỏng etcd cluster.

Upgrade — Nâng cấp

A/B Partition — Atomic Upgrade

Talos dùng cơ chế A/B partition: cài image mới vào partition B trong khi A vẫn chạy. Reboot sang B; nếu lỗi → tự động rollback về A.

Rolling Upgrade

bash
# Upgrade Talos OS (từng node, cordon+drain tự động)
talosctl upgrade --nodes 10.0.0.4 \
  --image ghcr.io/siderolabs/installer:v1.13.6

# --preserve giữ EPHEMERAL · --stage upgrade khi reboot
talosctl upgrade --nodes 10.0.0.1 --image ...:v1.13.6 --preserve --stage

# Upgrade Kubernetes (khác với upgrade OS!)
talosctl upgrade-k8s --to 1.36.2 --nodes 10.0.0.1
Thứ tự đúng
1 CP node → chờ healthy → CP tiếp theo → workers cuối. Luôn giữ quorum etcd.
Kiểm tra version skew
kubelet không được cách apiserver quá 3 minor version. Upgrade OS trước, K8s sau.

Disaster Recovery

etcd Snapshot & Restore

bash · etcd DR
# Backup — tạo snapshot etcd (lên lịch định kỳ!)
talosctl etcd snapshot db.snapshot --nodes 10.0.0.1

# Restore — recover từ snapshot khi mất quorum
talosctl bootstrap --recover-from ./db.snapshot --nodes 10.0.0.1

Kịch bản mất node

Kịch bảnTác độngCách xử lý
Mất 1 CP (trong 3)Vẫn quorumReset node → re-apply config → join lại
Mất 2 CP (trong 3)Mất quorumRestore từ snapshot (recover-from)
Mất workerPods rescheduleProvision worker mới, apply worker.yaml
Mất toàn bộ clusterFull outageRe-provision + etcd restore + GitOps re-sync
✅ DR Best Practice
Snapshot etcd tự động (CronJob) + lưu offsite. Giữ MachineConfig + manifests trong Git. Test restore định kỳ — backup chưa test = không có backup.

Airgap — Môi trường cô lập

Airgap = cluster không có internet (quốc phòng, ngân hàng, hạ tầng trọng yếu). Mọi image, installer, extension phải được mirror vào một private registry nội bộ.

yaml · registry mirrors
machine:
  registries:
    mirrors:
      docker.io:
        endpoints: ["https://registry.internal:5000"]
      ghcr.io:
        endpoints: ["https://registry.internal:5000"]
      registry.k8s.io:
        endpoints: ["https://registry.internal:5000"]

System Extensions

Vì rootfs immutable, muốn thêm driver/firmware/agent thì dùng System Extensions — được nhúng vào boot image lúc build, không cài lúc runtime.

🖥️ GPU Drivers
nvidia-container-toolkit, nonfree-kmod-nvidia
💾 Storage
iscsi-tools, drbd, zfs, util-linux-tools
🌐 Networking
tailscale, mellanox-ofed, intel firmware
🔧 Hardware
amd-ucode, intel-ucode, firmware blobs
🛡️ Security
tpm2, gvisor sandbox runtime
📊 Observability
Guest agents (qemu, cloud-init variants)
yaml · install.extensions
# Extensions được nhúng vào image qua Image Factory / imager
machine:
  install:
    extensions:
      - image: ghcr.io/siderolabs/nvidia-container-toolkit:...
      - image: ghcr.io/siderolabs/iscsi-tools:...
⚠️ Lưu ý
Thêm/bớt extension = image mới = phải upgrade node để áp dụng. Không có chuyện "cài nóng" extension trên node đang chạy.
15

Image Factory

Image Factory (factory.talos.dev) là dịch vụ build image tùy biến: chọn version + extensions + kernel args → nhận về một schematic ID và URL tải ISO/PXE/disk image.

bash · schematic
# schematic.yaml
customization:
  systemExtensions:
    officialExtensions:
      - siderolabs/iscsi-tools
      - siderolabs/util-linux-tools

# POST để lấy schematic ID
curl -X POST --data-binary @schematic.yaml https://factory.talos.dev/schematics
# → {"id":"abc123..."} — dùng ID này trong URL image

Talos & GitOps

Talos hợp với GitOps một cách tự nhiên: MachineConfig là YAML versioned. Kết hợp với Cluster API (CAPI) + Flux / ArgoCD để quản lý cả OS lẫn workload từ Git.

Cluster API (CAPI)
Provider CACPPT / CABPT quản lý vòng đời node Talos khai báo qua CRD.
Flux / ArgoCD
Reconcile workloads & add-ons từ Git. MachineConfig cũng có thể versioned và apply qua pipeline.

Kết luận

Talos Linux đại diện cho một cách tiếp cận triệt để: một OS chỉ làm đúng một việc — chạy Kubernetes. Bằng cách loại bỏ SSH, package manager, shell và biến root filesystem thành read-only, Talos giảm attack surface xuống mức tối thiểu và loại bỏ hoàn toàn configuration drift.

Với mô hình API-driven, MachineConfig versioned trong Git, và cơ chế A/B atomic upgrade, Talos biến việc vận hành fleet hàng nghìn node thành một quy trình khai báo, tự động và có thể tái tạo — đúng tinh thần immutable infrastructure.

FAQ

Câu hỏi thường gặp

Talos có SSH không?
Không. Talos loại bỏ hoàn toàn SSH. Mọi thao tác đi qua Talos API (gRPC, mTLS). Debug container dùng kubectl exec; debug node dùng maintenance mode.
Tôi cài thêm phần mềm lên node bằng cách nào?
Không cài trực tiếp. Driver/firmware/agent ở tầng OS dùng System Extensions (nhúng vào image). Phần mềm ứng dụng thì chạy như container trong Kubernetes.
Cần bao nhiêu control plane node?
Production nên 3 hoặc 5 (số lẻ để etcd giữ quorum). Single-node chỉ dành cho lab/dev.
Upgrade có gây downtime không?
Rolling upgrade từng node + A/B partition giúp giảm thiểu downtime. Với HA control plane (3/5 node) và workload phân tán, upgrade gần như không gián đoạn dịch vụ.
Talos chạy được ở đâu?
Bare-metal, VM (Proxmox, vSphere…), cloud (AWS, GCP, Azure…), edge, và airgap. Cloud-agnostic hoàn toàn.
